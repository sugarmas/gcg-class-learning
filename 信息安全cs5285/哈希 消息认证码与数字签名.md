# 哈希 消息认证码与数字签名

Lecture 5：完整性（integrity）与不可否认性（non-repudiation）。三者是递进关系——哈希是构件、MAC 给双方认证、数字签名才给不可否认。

## 完整性

加密只提供 confidentiality，**不保证完整性**：攻击者仍可改、删、插消息或伪造来源。完整性分三层：检测（意外）修改 → data origin authentication → non-repudiation。

## 哈希函数

功能性质：**压缩**（任意长输入→定长输出）、**易计算**。
三个安全性质：
1. **One-way（preimage resistance）**：给定 $y$ 找不到 $x$ 使 $h(x)=y$；
2. **Second preimage resistance**：给定 $y$ 和 $h(y)$，找不到 $x\ne y$ 使 $h(x)=h(y)$；
3. **Collision resistance**：找不到任意 $x\ne y$ 使 $h(x)=h(y)$。

压缩必有碰撞，故只要求「找到碰撞困难」。**碰撞抵抗 ⇒ 单向**（反之不成立）。**哈希本身不提供任何安全服务**——无 key、人人可算，只能检测意外修改，须与其他机制配合。

**生日问题**：K 人中有两人同日生、概率达 1/2 只需 $K=23$（约 $\sqrt{365}$）。攻击者随机取约 $2^{N/2}$ 条消息即以 ≈1/2 概率找到碰撞。所以**N-bit 哈希的碰撞抵抗只有 $2^{N/2}$ 安全**（40-bit 摘要约 $2^{20}$ 即可破）。数字签名依赖抗碰撞，故摘要必须足够长。

流行算法：MD4、MD5（128-bit）、SHA-1（160-bit）、SHA-2（224/256/384/512）、SHA-3（Keccak，sponge 结构）。MD5 与 SHA-1 **均已破**（SHA-1 碰撞约 $2^{69}$，低于生日的 $2^{80}$），不能再用于签名。结构：Merkle-Damgård（分块+压缩函数迭代，MD5/SHA-1/SHA-2）vs sponge（SHA-3）。

## MAC（消息认证码）

对称机制：双方共享 key $K$，用 (消息, K) 算 tag 附在消息后；接收方重算比对。提供 **integrity + data origin authentication**（只有持 K 的人能算），**不提供 non-repudiation**（双方都能造，无法向第三方证明是谁发的）。

- **CBC-MAC**：用块密码 CBC（IV=0），取最后一块密文作 tag。**变长消息不安全**——可长度扩展伪造（由 $(P_1P_2,T')$ 与 $(P_3,T'')$ 拼出 $P_1P_2P_3T'$ 的合法 tag $T''$）。
- **HMAC**：$HMAC_K(M)=H\big((K\oplus opad)\,\|\,H((K\oplus ipad)\,\|\,M)\big)$，其中 ipad、opad 是固定常量重复到块长（ipad=0x36、opad=0x5C）。广泛用于 IPSec / VPN。
- **易错点**：直接 $H(K\|M)$ **不安全**——Merkle-Damgård 的**长度扩展攻击**可续接数据；HMAC 的双层结构正是为规避它（PS1 问过这点）。

加密 + 完整性并存时，**Encrypt-then-MAC** 更安全；或用自带两者的 Authenticated Encryption（如 GCM）。

## 数字签名

非对称：**用私钥签、用公钥验**。只有签者能生成有效签名，任何人都能验证。

- 提供 **data origin authentication + non-repudiation**——这正是 MAC 给不了的那一层。
- **RSA 签名**：$S=h(M)^d\bmod n$，验证 $S^e\bmod n\overset{?}{=}h(M)$。
- **术语警告**：签名不等于「用私钥加密」、验证不等于「用公钥解密」——只是 RSA 恰好两个方向都可算；DSA / ElGamal 签名不适用这种说法。
- **为什么先哈希**：消息可能大于 $n$ 无法直接签；先签 $h(M)$ 同时解决长度与效率。
- RSA 验证能还原出 $h(M)$ 本身 = **signature with message recovery**；ElGamal / DSA 是 **signature with appendix**（签名附在消息旁）。ElGamal/DSA 签名基于 DLP。
- **Padding oracle**：解密实现若泄露可区分的「填充错误」（PKCS7），攻击者每字节最多 256 次即可逐字节恢复；Lucky Thirteen 用计时错误达到同样效果。
