# 数据获取 爬虫

CS5481 第 2 讲。回答"数据从哪来、怎么拿进来"：三类主力数据源（关系库 / 平面文件与 XML / API 与 web 服务）、web scraping 的具体做法与礼节，以及 scraping 与 crawling 的分界。

## 数据源类型

### 1. 关系数据库

组织内部的数据库 / 数据仓库支撑日常业务，典型四类场景，都用"主表 + 外键关联"组织：

- 零售库存：`Products(ProductID, Name, Category, Price, Stock)` × `Sales(SaleID, ProductID, Date, Quantity)`
- 电商交易：`Customers` × `Orders` × `OrderDetails`
- HR 招聘：`Applicants` × `JobPositions` × `Applications(Status)`
- 制造工作流：`Projects` × `Tasks` × `Employees`

用 **SQL** 抽取：指定取什么、从哪张表、如何分组、结果排序、返回条数。非关系库也可用 SQL 或 SQL-like：**CQL**（Cassandra）、**GraphQL**（Neo4j）。

### 2. 平面文件与 XML 数据集

外部（公开或私有）数据集常以 flat file / spreadsheet / XML 提供。**Flat file** 的特点是：纯文本、一行一记录、值由 delimiter 分隔、**所有数据映射到单张表**，最常见格式是 `.CSV`。常见文件格式：CSV、XLSX、HTML、XML、**PDF**、**JSON**（专为 web 上传输 structured data 的文本标准）。

### 3. API 与 web 服务

三个概念要分清：

- **API** = 软件组件之间交互的规则与接口（不一定要联网）
- **Web Service** = 经由网络（通常 HTTP）暴露功能或数据的服务
- **Web API** = 访问 Web Service 所用的那套 API

API 从 endpoint（数据库、web 服务、data marketplace）取数，返回 plain text / XML / HTML / JSON / 媒体文件；也常用于数据校验（如清洗、关联数据）。

### 其他来源

- **数据流与 feeds**：来自仪器、IoT、车载 GPS、程序、网站、社交网络的持续流；web feed 是"频繁更新内容"的数据格式。处理技术：**Kafka**（分布式事件存储与流处理，高吞吐、低延迟）、**Storm**（分布式流计算）。
- **Sensor data**：可穿戴、智慧城市、医疗设备等。
- **Data exchange**：数据提供方与消费方之间**自愿共享**的第三方数据。
- **Surveys / Census / Interviews / Observation studies**：问卷、人口普查、访谈（质性数据）、观察。

## Web scraping 的做法

**定义**：构建一个 agent，自动地 download、parse、organize 网页数据；从互联网的非结构化来源抽取相关数据。别名 screen scraping / web harvesting / web data extraction；可抓文本、联系方式、图片、视频、商品等。工具：**BeautifulSoup、Scrapy、Pandas、Selenium**。

技术链路：

1. 网页跑在 **HTTP** 上（OSI 七层模型的 application layer）。核心是"HTTP request → HTTP response"，response body 通常是 HTML。
2. **HTML** 是标准标记语言，由成对的 tag 提供结构与格式。Python 的 `requests` 取回 HTML 文本。
3. **HTML parsing** = tokenization + tree construction：token 包括 start/end tag、属性名与值；文档 well-formed 时解析更快，最终构建出 document tree。
4. 抓取流程三步：**identify data → scrape → import**。识别数据又有三步：确定要收集什么信息、写收集计划（时间窗、多少数据才算 credible、依赖/风险/缓解）、确定收集方法（取决于来源、数据类型、时间窗、数据量）。

**具体例子（Assignment01 / Tutorial2）**：用 `requests` 加 `User-Agent` 头（伪装浏览器防屏蔽）取 MAL Top Anime；`soup.select('tr.ranking-list')` 定位每行，`div.information` 里的 `"TV (28 eps) Sep 2023 - Mar 2024 1,511,081 members"` 用 **正则** 拆出 type / episodes / year / members（注意 `1,511,081` 要去掉逗号）；翻页用 `limit` 参数 `range(0,250,50)`，每页后 `time.sleep(0.5)` 放慢；最后 `to_csv`。

## 合法性与礼节

讲义给出的约束是"礼节"层面的：

- **robots.txt**：1994 年起的协议，网站把 `/robots.txt` 放在服务器根目录，声明哪些部分可/不可被抓。
- **Implicit politeness**：即便站点没有声明，也不要过于频繁地打同一站点（对应代码里的 `sleep`、限速）。

法律层面讲义未展开，实践上应以站点声明与条款为准——此处标注为不确定。

## 从 scraping 到 crawling

| | Web Scraping | Web Crawling |
|---|---|---|
| 定义 | 抽取**大量特定数据**，通常来自单个网页/站点 | 读取、复制、存储网页内容，用于**归档或索引**；处理的是一整个网页网络 |
| 使用方 | 大小企业都用 | 通常只有大公司（搜索引擎） |
| 场景 | 比价、股市分析、品牌声誉、学术研究 | 生成搜索结果、SEO 监控、网站分析 |

Crawler 本质是**图的遍历/搜索算法**（沿链接扩展）。任何 crawler 必须：

- **Robust**：能抵挡 spider trap 等来自服务器的恶意行为
- **Polite**：遵守显式（robots.txt）与隐式（别打太频繁）的礼节

调度上，爬取频率受 politeness 约束（即隐式的 crawl delay），robots.txt 决定哪些部分可抓——这一层就是"调度"的边界，讲义未给出更细的队列/优先级算法。
