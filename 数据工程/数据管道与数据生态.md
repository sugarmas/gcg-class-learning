# 数据管道与数据生态

CS5481 第 1 讲。这是整门课的骨架：先记住数据工程不是"写模型"，而是**把数据从各处可靠地搬到能用**——其余各讲都是这条管道上的一个环节。

## 数据工程的定义

**Data Engineering** = 设计并构建"大规模地采集（collecting）、存储（storing）、分析（analyzing）数据"的系统。它的目标不是模型本身，而是提供**有组织、标准化的数据流**（organized, standard data flow），好让下游的 ML / 数据分析能跑起来。风险由一句老话概括：**GIGO（garbage in, garbage out）**——没有高质量数据，就没有高质量的挖掘结果。

## Data pipeline（数据管道）

主线是三段：

- **Data acquisition** 采集
- **Data processing** 处理
- **Data storage** 存储

再加一层 **data management**（索引、查询、治理）。工程上最常见的形式是 **ETL（Extract–Transform–Load）**：把多源原始数据抽取、转换、合成后，加载进 data warehouse / data lake / 关系库等。

## 数据生态（ecosystem）的层次

- **数据源**：格式极杂，从关系库到网页，见 [[数据获取 爬虫]]
- **存储**：分 OLTP 与 OLAP 两类（见下）
- **Data integration**：把多个 disparate sources 合成一个 unified view 供查询
- **Data analysis**：发现有用信息、支撑决策，常借助 data mining / ML
- **Data visualization**：BI 与 reporting 工具，交互式 dashboard，实时或定时呈现
- **数据驱动应用**：information retrieval（从资源集中取回相关信息）、recommender system（预测用户对 item 的 rating/preference）、social network analysis（用图论刻画 nodes/ties）、anomaly detection（罕见、显著偏离常态的点，又称 outlier/noise/novelty）
- **Data governance**：data quality（accuracy、completeness、consistency、validity、uniqueness、biasness、timeliness）、data security、data privacy

### OLTP vs OLAP

| | OLTP | OLAP |
|---|---|---|
| 用途 | 存放高频的日常运营数据 | 做复杂数据分析 |
| 形态 | 通常关系型，也可非关系 | 关系与非关系库、data warehouse、data mart、data lake、big data store |

## 数据类型的三种分类

- **Structured**：格式刚性，可存进 well-defined schema，能用行列（rows/columns）表示，是客观的事实与数字。
- **Semi-structured**：有一些组织属性但没有固定 schema，靠 tags / elements / metadata 分层组织，不能用行列存；典型是 **XML 与 JSON**。
- **Unstructured**：没有易识别的结构，无法塞进行列，不遵循特定格式/序列语义/规则；如文本、图像、音频。

## 角色与工具

数据相关工作的技能是三维交集：**coding + maths + domain knowledge**。语言分三类：

- **Query languages**：SQL。可移植、平台无关，语法接近英文，解释器执行，能高效检索大量数据。
- **Programming languages**：Python（易学、开源、库全）、R（统计）、Java（Hadoop/Hive/Spark 等大数据框架，适合 speed-critical 项目）。
- **Shell & scripting**：文件操作、备份、批处理、系统管理；PowerShell 是 object-based 的，能对管道中的对象 filter/sort/group。
